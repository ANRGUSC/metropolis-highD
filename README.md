# metropolis-highD

Numerical calculations and figures for Metropolis random walks escaping deep cubic basins in higher dimensions.

The notebook studies the potential `V(x) = ||x||_inf` on the integer lattice, with nearest-neighbor proposals, uphill acceptance probability `p`, and absorption at shell `N`. It compares the true-chain mean escape time `H_D(N)` with the shell-quotient mean `Q_D(N)` in dimensions 1, 2, and 3. Time counts attempted moves, including rejected proposals.

## Contents

- [Numerical calculations notebook](Metropolis_Numerical_Calculations_Figures.ipynb): computes a shared dataset, paper Figures 4 and 5, supplementary Figures S1-S3, numerical checks, and optional high-precision audits.
- [Paper (PDF)](paper/Metropolis_Walks_in_Higher_Dimensions.pdf): accompanying manuscript.
- [LICENSE](LICENSE): BSD 3-Clause license.

The paper's Figures 1-3 illustrate geometry and network arguments and are not generated by this notebook. Supplementary Figures S1-S3 are additional repository plots, not figures in the paper or a separately published supplement.

## Run the notebook

Open the notebook in [Google Colab](https://colab.research.google.com/github/ANRGUSC/metropolis-highD/blob/main/Metropolis_Numerical_Calculations_Figures.ipynb) and select **Runtime > Run all**.

Alternatively, install the Python dependencies and launch Jupyter locally:

```sh
python -m pip install jupyter numpy pandas scipy matplotlib mpmath
jupyter notebook Metropolis_Numerical_Calculations_Figures.ipynb
```

Run all cells in order. The configuration cell sets the supplementary figure grids and validation options. High-precision audits run by default; set `RUN_MPMATH_AUDIT = False` to skip them. The expensive audit at `(D, N, p) = (3, 25, 0.15)` is disabled by default and can be enabled with `RUN_HARDEST_D3_AUDIT = True`.

Results are written to `metropolis_results/` under the working directory. The final cell creates `metropolis_results.zip` alongside that folder and downloads it automatically in Colab. For a local run, it prints the ZIP path.

The notebook computes the union of the supplementary grids once and saves it as `data/all_results.csv`. Paper Figures 4 and 5 read subsets of these data without additional solves. Their grids are fixed independently of the supplementary settings: if a configuration change omits a required paper point, the paper cells raise an error identifying the missing parameters.

## Numerical method and validation

All plotted true-chain means use exact sign/permutation-orbit lumping, a regenerative identity, and a float64 sparse LU solve. The solver rejects componentwise backward errors above `1e-9` and, by default, relative disagreement between two LU orderings above `1e-8`. The shell-quotient mean uses the closed-form sum in Theorem 1, Eq. (17). The notebook does not use Monte Carlo simulation.

Validation includes 25 base checks covering analytic identities, agreement with independent full-lattice solves, a numerical reference, and finite-depth dimensional reversal. Two additional checks examine the `N = 2` reversal threshold and the `p = 1` Brownian constant. Ten checks confirm the numerical values quoted in Section VI at their displayed precision, including the shallow-basin reversal example.

By default, independent block-Thomas audits run at 60 and 90 digits for `(D, N, p) = (2, 23, 0.20), (3, 8, 0.20), (2, 25, 0.15), (3, 10, 0.15)`. The paired reference results must agree within relative tolerance `1e-15`, and the float64 solver must agree with the reference within `1e-10`. These audits check selected results; they do not supply plotted values. References are converted to float64 before comparison, so the paired check establishes agreement at double precision, not to 60 digits.

The shell-quotient formula equals the true-chain mean in one dimension; for higher dimensions it describes a different chain. Comparisons on the configured grid are numerical observations, not a general inequality. Residual and LU-ordering checks do not bound forward error.
